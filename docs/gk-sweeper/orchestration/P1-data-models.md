# P1 데이터·학습 부품 — S02~S05

### S02 · 분석 프레임 적재 (기획서 3-2~3-4절) → E01
1. **담당:** data-engineer
2. **할 일:** `load_frames.py`를 구현해 다음을 처리한다. 좌표 변환, 골키퍼 식별, 결측 프레임 제거, 팀·하프별 방향 회전, Savitzky–Golay 속도(창 7, 1차, 상한 12 m/s), 소유 시퀀스 분할(5프레임 미만 깜빡임 병합, 시작 후 2초), 공 소유자 조건(2 m), |B| ≥ 30 m, 1초 창마다 첫 프레임 선정, 3-4절 상황 변수. 결과는 `frames.parquet`에 저장하고, 좌표 회전·시퀀스 분할·골키퍼 식별에 pytest를 둔다.
3. **얻고자 하는 것:** 분석 프레임 표(예상 7,000~10,000개), 사유별 제외 개수, 경기별 프레임 수와 시퀀스 수, 상황 변수의 분포.
4. **목적:** 이후 모든 계산의 입력이 되는 표본을 기획서 정의대로 확정한다. RQ2의 설명변수도 여기서 만들어진다.
5. **유의사항:**
   - 필터를 적용하는 순서를 3-3절 그대로 지킨다(alive와 결측 → 시퀀스 → 공 소유자 → 거리 → 1초 창).
   - 속도는 프레임을 고르기 전에 25 fps 연속 구간에서 계산한다.
   - 예상 규모를 크게 벗어나도 기준을 바꾸지 않는다. 사실 그대로 보고한다.
- **완료 기준:** pytest 통과, 감사 통과, E01 작성.

### S03 · StatsBomb 학습 부품 (4-3절) → E02
1. **담당:** stat-modeler
2. **할 일:** `models_sb.py`에서 다음을 처리한다.
   - 좌표를 변환하고, 공통 필터를 적용한다(남자 경기, freeze 있음, 오픈플레이, 헤더 제외, 골키퍼 좌표 있음).
   - xG_set을 GAM s(거리) + s(개방각)으로, xG_empty를 거리 로지스틱으로 맞춘다.
   - p_shot은 2015/16 프리미어리그 Ball Receipt\*로 라벨을 만들어 GAM으로 맞춘다.
   - 항별 외삽 한계 ρ(99번째 백분위)를 구하고, 경기 단위 5겹 교차검증으로 로그손실·Brier를 StatsBomb `xg`와 비교한다.
3. **얻고자 하는 것:** 저장된 모델 3개와 외삽 한계 3개, 표본 크기 대조(51,899 / 46,825 / 427), 교차검증 지표.
4. **목적:** S(득점 항)의 학습 부품을 확정한다. 골키퍼 위치를 입력에 넣지 않아 교란을 피한다(2절 설계 원칙).
5. **유의사항:**
   - 표본 크기가 기획서 수치와 다르면 멈춘다.
   - p_shot 라벨 규칙(건너뛸 행동, 다른 선수의 터치, 지정 행동 없이 소유가 끝나는 경우)을 4-3절 그대로 구현한다.
   - 모델은 GPU 코드가 읽을 수 있는 형태(계수나 격자 조회표)로도 저장한다.
- **완료 기준:** 표본 크기 일치, 교차검증 표 산출, 감사 통과, E02 작성.

### S04 · c·s_w 최대우도 추정 (4-4절) → E03
1. **담당:** stat-modeler
2. **할 일:** A(r)까지의 해석적 거리 함수와 w 정규화를 구현하고 pytest로 확인한다. 중간 표본 M(4,647개)을 `match_id` 짝·홀로 나누고, 짝수 쪽에서 c ∈ [−2, 2], s_w ∈ [0.05, 1.5]를 함께 최대우도로 추정한다. 경기 단위 부트스트랩 구간과 ρ(c, s_w)도 구한다.
3. **얻고자 하는 것:** c와 s_w의 추정값과 구간, 경계에 닿았는지 여부, ρ 값. 그리고 4-4절 규칙에 따라 정해지는 주 설정(경계면 c = −0.7)과 5-6의 c 민감도 범위.
4. **목적:** 골키퍼 전진의 손실 경로인 w를 데이터로 보정한다.
5. **유의사항:**
   - 슈팅 순간 조건(|r − B| = 0, τ = 0, g = 실제 위치)과 p_shot 제외를 지킨다. 홀수 쪽은 S15를 위해 손대지 않는다.
   - A(r) 거리 함수는 S06의 OBSO 구현과 **같은 코드**를 쓴다.
   - 경계 판정과 |ρ| > 0.9 규칙은 기획서 문장 그대로 적용한다.
- **완료 기준:** 추정과 규칙 적용 완료, pytest와 감사 통과, E03 작성.

### S05 · 좌표·동기화 검증 (5-1·5-2) → E04
1. **담당:** data-engineer
2. **할 일:**
   - 5-1: 모든 alive 프레임에서 팀·하프별로 골키퍼 x와 L − x_GK의 중앙값을 구한다.
   - 5-2: 이벤트를 가장 가까운 프레임에 대응시키고 패스 시작 좌표와의 거리 중앙값을 본다. 3 m를 넘으면 하프별 오프셋을 −2~+2 s에서 탐색한다.
3. **얻고자 하는 것:** 5-1의 범위 판정(x 5~25 m, 간격 10~35 m, 부호)과 5-2의 거리 중앙값, 적용한 오프셋.
4. **목적:** 좌표 회전과 이벤트 동기화가 맞는지 확인한다. 5-3과 b 추정이 이벤트에 의존하기 때문이다.
5. **유의사항:**
   - 5-1 실패로 변환을 고치면 S02를 다시 돌린다.
   - 고친 뒤에도 범위를 벗어나거나, 오프셋 탐색 후에도 3 m를 넘으면 멈추고 질의한다(기획서에 대처가 없음).
- **완료 기준:** 두 판정 모두 통과, 감사 통과, E04 작성.
