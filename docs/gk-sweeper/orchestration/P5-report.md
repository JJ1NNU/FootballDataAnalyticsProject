# P5 레포트 — S19~S21 (체크포인트 12-12)

### S19 · 그림 정비 (8절)
1. **담당:** analyst
2. **할 일:** 기획서 8절의 그림을 `figures.py` 하나로 다시 만들 수 있게 정리한다. 대표 장면 3~5개(Riemann 경기 포함)의 곡선과 C·S·O 지도, RQ2 계수표와 구간 지도, RQ3 분포, 검증·민감도 표.
3. **얻고자 하는 것:** 레포트와 슬라이드에 그대로 쓸 수 있는 그림 세트. 그림마다 한 문장 메시지를 단다.
4. **목적:** 사용자가 슬라이드를 직접 만들 때 필요한 시각 재료를 제공한다.
5. **유의사항:**
   - 대표 장면 선정 기준은 브리프 단계에서 사용자에게 질의한다(기획서에 기준이 없음).
   - 같은 변수는 모든 그림에서 같은 색과 단위를 쓴다.
- **완료 기준:** 그림 재생성 스크립트가 동작함, 그림 목록을 레포트에 연결함.

### S20 · 요약 종합과 전체 교정
1. **담당:** report-writer. 수치 대조는 spec-auditor가 맡는다.
2. **할 일:**
   - `00-summary.md`를 쓴다. 담을 내용: 연구 질문, RQ별 결론, 핵심 그림, 전체 discussion, 6절 한계, 명세에서 달라진 점과 결정 로그 요약.
   - E01~E16 전체를 다시 읽고 용어, 기호, 문체를 통일한다.
3. **얻고자 하는 것:** 사용자가 처음부터 끝까지 읽고 연구를 설명할 수 있는 레포트 묶음.
4. **목적:** 최종 발표(12-21) 준비의 기반 자료를 완성한다.
5. **유의사항:**
   - 결론에는 "방향 확인"과 "강건"을 모두 충족한 계수만 쓴다(4-6절).
   - 표본의 한계(7경기, 그중 5경기가 같은 팀, 골키퍼 10명)를 결론 바로 옆에 적는다.
   - 파일당 70줄 안팎을 목표로 하고, 문장을 다듬는 데 시간을 쓴다.
- **완료 기준:** spec-auditor의 수치 대조 통과, 사용자 검토 요청.

### S21 · 최종 감사와 재현성 점검
1. **담당:** spec-auditor(감사), 총괄(재현 실행과 정리)
2. **할 일:**
   - 새 환경에서 `requirements.txt` → CPU 단계 → 그림 생성을 다시 실행해, 주요 수치가 일치하는지 확인한다.
   - Kaggle 결과는 해시로 대조한다.
   - 기획서, 결정 로그, 레포트가 서로 일치하는지 확인한다.
   - README 현황표를 마감한다.
3. **얻고자 하는 것:** 재현성 확인서(레포트 부록)와 정리된 저장소.
4. **목적:** 발표 이후에도 결과를 다시 만들 수 있게 하고, 숨은 불일치를 없앤다.
5. **유의사항:** 불일치가 나오면 레포트를 고치기 전에 원인을 보고하고 질의한다. PR은 사용자가 요청할 때만 만든다.
- **완료 기준:** 감사 통과, 커밋과 푸시, 사용자에게 최종 보고.
