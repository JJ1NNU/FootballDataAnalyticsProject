# P3 GPU·본 계산 — S09~S12 (체크포인트 12-06)

### S09 · GPU FP32 구현
1. **담당:** obso-engineer
2. **할 일:**
   - `obso_torch.py`를 만든다. S06과 같은 입력과 출력을 갖고, 계산은 FP32 텐서로 하되 O의 합산은 FP64로 한다.
   - 프레임 × 깊이 × 칸을 배치로 묶어 벡터화한다.
   - `run_counterfactual.py`에 `--device`, `--shard k/2`, 청크 저장, 이어서 계산 기능을 추가한다.
   - 5-6의 값싼 변형을 본 계산 루프 안에서 함께 계산하게 한다.
   - 이 클라우드의 CPU(torch CPU 모드)에서 S06 정답지와 대조한다.
3. **얻고자 하는 것:** GPU에서 그대로 돌릴 수 있는 계산 코드와, CPU 모드 기준 FP32와 FP64의 차이 측정값.
4. **목적:** 본 계산과 비싼 민감도 항목을 Kaggle T4×2에서 기한 안에 끝낼 수 있게 한다.
5. **유의사항:**
   - FP16, AMP, DataParallel은 쓰지 않는다. GPU 2장은 프레임을 반씩 맡는 독립 프로세스 2개로 돌린다.
   - 로직을 바꾸지 않는다. 결과가 다르면 GPU 쪽을 고친다. 정답지는 CPU 구현이다.
   - VRAM 16 GB × 2에 맞춰 배치 크기를 정하는 기준을 문서화한다.
- **완료 기준:** CPU 모드 대조에서 최대 절대 차이 ≤ 10⁻⁷, pytest 통과, `/code-review` 처리.

### S10 · Kaggle 연동
1. **담당:** 총괄(자격증명 폼), kaggle-runner(실행), data-engineer(입력 패키징)
2. **할 일:**
   - 총괄이 `request_credential`로 Kaggle 토큰을 등록한다. 사용자는 Settings → API → Create New Token으로 발급한 토큰을 폼에 입력한다.
   - kaggle CLI를 설치한다.
   - 비공개 Dataset을 만든다. 담을 것: 프레임, 21명 좌표와 속도, 모델 계수, 설정, 코드.
   - T4×2 스모크 테스트 kernel을 돌린다. GPU 2장 인식, torch 버전, 작은 배치 실행을 확인한다.
   - `kaggle-log.md`를 만든다.
3. **얻고자 하는 것:** API로 제출하고 결과를 받아 오는 경로가 실제로 동작한다는 확인. GPU 2장 인식, 비공개 설정, 실행 시간 기록 형식.
4. **목적:** 본 계산 전에 연동 문제를 분리해 해결하고, 쿼터를 낭비하지 않게 한다.
5. **유의사항:**
   - 토큰은 채팅으로 받지 않는다. Dataset과 kernel은 반드시 비공개로 만든다.
   - Kaggle에 휴대폰 인증이 안 되어 있으면 GPU를 쓸 수 없다. 이 경우 사용자에게 알린다.
   - 프록시가 Kaggle 요청을 막으면 환경 설정 문서를 읽고 사용자에게 알린다.
- **완료 기준:** 스모크 테스트 성공과 결과 다운로드, 쿼터 기록.

### S11 · 예비 실험 (4-7절) → E08
1. **담당:** obso-engineer(분석), kaggle-runner(GPU 실행)
2. **할 일:** 무작위 200프레임(시드 2026)으로 4-7절의 1~5번을 수행한다.
   - 1번 계산 시간: T4×2에서 FP32로 잰다.
   - 2번 구현 대조: LaurieOnTracking 기준 0.01 이하, GPU FP32와 CPU FP64 차이 10⁻⁷ 이하.
   - 3번 기초 수치, 4번 분해 곡선, 5번 판단.
3. **얻고자 하는 것:** 4-7절 규칙으로 정해지는 표본 간격(1초 또는 2초)과 깊이 간격(2 m 또는 4 m), 본 계산의 예상 GPU 시간, 기초 수치와 분해 결과.
4. **목적:** 본 계산의 설정과 비용을 확정하고, 곡선이 의미 있는 모양을 갖는지 미리 확인한다.
5. **유의사항:**
   - 시간 기준(0.1초, 24시간)은 기획서 문장 그대로 적용한다.
   - 예상 시간이 Kaggle 한도(세션 12시간, 주 30시간)를 넘으면 멈추고 질의한다.
   - 평균 w > 0.05 같은 결과는 진행 조건이 아니다. 6절 한계에 기록할 사항이다.
   - 이 200프레임은 본 표본에 포함된다.
- **완료 기준:** 두 대조 기준 통과, 설정 확정, 감사 통과, E08 작성.

### S12 · 본 계산 (4-1·4-5절) → E09
1. **담당:** kaggle-runner. 결과 검사는 obso-engineer가 맡는다.
2. **할 일:** 확정된 설정으로 전체 프레임을 계산한다. 값싼 민감도 변형과 b 세 값을 포함하며, GPU마다 샤드 하나씩 맡긴다. 결과를 받아 `curves.parquet`와 `metrics.parquet`로 합치고, 무결성을 검사한다. 검사 항목은 프레임 누락, NaN, 곡선 길이, 무작위 20프레임의 CPU 재계산 대조다.
3. **얻고자 하는 것:** 모든 분석의 입력이 되는 곡선과 지표 표, GPU 사용 시간 기록.
4. **목적:** RQ1~RQ3와 5-5·5-6의 원재료를 한 번의 계산으로 확보한다.
5. **유의사항:**
   - 세션이 12시간을 넘지 않게 샤드와 청크를 나눈다. 실패한 청크만 다시 제출한다.
   - 파일이 50 MB를 넘으면 커밋하지 말고 질의한다.
   - 이 단계는 해석하지 않는다. 계산과 검사만 한다.
- **완료 기준:** 무결성 검사 통과, 커밋, E09 작성. **12-06 체크포인트를 점검한다.**
