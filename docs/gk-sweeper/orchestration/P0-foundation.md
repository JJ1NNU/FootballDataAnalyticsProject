# P0 기반 — S00·S01

### S00 · 기획서 전체 명세 감사와 빈칸 질의
1. **담당:** spec-auditor(모드 1, 전체 범위). 질의는 총괄이 `grilling` 형식으로 진행한다.
2. **할 일:** 기획서 1~9절 전체를 단계 S02~S18 단위로 나눠 읽는다. 단계마다 입력, 출력, 파라미터, 판정 기준, 실패 시 대처를 표로 만들고, 구현에 필요한데 적혀 있지 않은 것을 빈칸 목록으로 뽑는다. 예를 들면 결측과 경계 처리, 동점 처리, 판정 실패 시 대처, 단위, 정의가 서로 충돌하는 곳이다.
3. **얻고자 하는 것:** 단계별 빈칸 목록과, 그에 대한 사용자 결정. 결정은 기획서 본문과 `decisions.md`에 반영한다.
4. **목적:** 구현 도중 에이전트가 빈칸을 추측으로 채우는 일을 미리 막는다. 질의를 한곳에 모아 사용자의 응답 부담과 일정 지연을 줄인다.
5. **유의사항:**
   - 빈칸을 "합리적 기본값"으로 채우지 않는다. 추천안은 질문에 붙이기만 한다.
   - 질문이 많으면 선행 관계에 따라 라운드로 나눈다. 앞선 결정에 달린 질문은 다음 라운드로 미룬다.
   - 여기서 놓친 빈칸은 각 단계의 브리프에서 다시 잡는다. S00이 모든 빈칸을 잡았다고 가정하지 않는다.
- **완료 기준:** 빈칸 목록이 모두 결정되거나 "단계 브리프에서 결정"으로 명시적으로 미뤄짐. 기획서 수정을 커밋함.

### S01 · 환경·코드 골격·원자료 확보
1. **담당:** data-engineer. 감사는 spec-auditor가 맡는다.
2. **할 일:**
   - `requirements.txt`를 만든다. kloppy 3.19.1, pygam, statsmodels, scipy, pyarrow, statsbombpy, pytest의 버전을 고정하고, GPU용 torch는 Kaggle 기본 버전을 기록한다.
   - `scripts/gk_sweeper/`에 기획서 8절의 파일 골격과 공통 설정(`config.py`: 시드, 경로, 파라미터 표)을 만든다. `tests/`도 만든다.
   - IDSSE 7경기의 트래킹, 이벤트, 메타데이터를 `data/raw/`에 받는다. StatsBomb 2015/16 프리미어리그 원본 이벤트도 받는다.
   - 기획서 3-1절의 실측 사실을 다시 확인한다. 7경기 모두 105 × 68 m인지, 선발 골키퍼 10명, 슈팅 100,864행.
3. **얻고자 하는 것:** 어떤 세션에서든 같은 결과가 나오는 실행 환경, 파라미터를 한곳에서 관리하는 설정 파일, 3-1절 사실과의 대조표.
4. **목적:** 이후 모든 단계가 같은 버전, 같은 상수, 같은 원자료 위에서 돌게 한다. 컨테이너가 바뀌어도 재현할 수 있게 한다.
5. **유의사항:**
   - 파라미터 값은 기획서 4-0절 표와 4-2~4-4절에서 그대로 옮기고, 항목마다 조항 번호를 주석으로 단다.
   - 3-1절 사실과 하나라도 다르면 멈추고 보고한다.
   - 원자료는 커밋하지 않는다(`data/raw/`는 git 제외).
- **완료 기준:** `pytest`가 통과함(골격 수준). 3-1절 대조표에 불일치가 없음. 커밋함.
