# 연구 단계 실행 절차 (총괄용)

인자로 단계 번호를 받는다. 없으면 `docs/gk-sweeper/orchestration/README.md` 현황표에서 첫 미완료 단계를 고른다.

## 0. 준비
- README 현황표, 해당 페이즈 파일(`P*.md`)의 단계 정의, `docs/gk-sweeper/decisions.md`를 읽는다.
- 체크포인트 날짜를 넘겼으면 진행 전에 사용자에게 기획서 9절 생략 적용 여부를 질의한다.
- 현황표에서 그 단계를 `진행 중`으로 바꾼다.

## 1. 브리프 — spec-auditor(모드 1)
- 단계 정의와 관련 기획서 절 번호를 넘기고 브리프를 받는다.
- 빈칸이 있으면 → 4번(질의)으로 간다. 빈칸이 없을 때만 착수한다.

## 2. 실행 — 단계 정의의 담당 에이전트
- 프롬프트에 브리프 전문, 산출물 경로, 완료 기준, 유의사항, 멈춤 규칙을 넣는다.
- 서로 독립인 작업만 병렬로 돌린다. 긴 계산은 백그라운드로 돌리고 완료 알림을 기다린다.
- 에이전트가 질문 목록을 들고 멈추면 → 4번으로 간다.

## 3. 검증
- 코드가 바뀐 단계는 `/code-review`(medium)를 돌리고, 지적 사항을 담당 에이전트에게 고치게 한다.
- spec-auditor(모드 2)로 감사한다. 조건부나 불합격이면 2번으로 돌아간다(같은 원인으로 2회 실패하면 4번으로 간다).
- report-writer에게 실험 파일을 쓰게 하고, spec-auditor에게 수치 대조를 한 번 더 맡긴다.

## 4. 질의 (필요할 때만)
- `grilling` 스킬 형식으로 질문마다 추천안과 근거를 붙여 사용자에게 묻고, 답을 기다린다.
- 답을 받으면 기획서 본문을 고치고, `decisions.md`에 `D-xxx` 항목(날짜, 질문, 결정, 반영 위치)을 추가한 뒤 1번부터 다시 진행한다.

## 5. 마무리
- 현황표를 `완료(날짜)`로 바꾸고 산출물 링크를 단다. 커밋하고 `claude/gallant-planck-vxd3gb`에 푸시한다.
- 사용자에게 보고한다. 담는 내용: 한 일, 핵심 수치, 판정, 명세와 다른 점, 다음 단계와 그 단계의 질의 예정 사항.
- **사용자 승인 없이 다음 단계로 넘어가지 않는다.**

## 금지
- 브리프의 빈칸을 총괄이나 에이전트가 추측으로 채우는 것.
- 판정 기준에 미달했는데 "대체로 괜찮다"며 진행하는 것.
- 테스트를 끄거나 건너뛰어 통과시키는 것.
